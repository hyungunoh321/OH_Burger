# 데모 영상 시나리오

데모 영상(#10)을 찍을 때 보는 대본이다. 영상은 **시나리오별 데모**를 먼저 하고 **코드 설명**을 뒤에 붙인다.
기능을 먼저 보여 주고, 코드 설명에서 "앞에서 본 그 기능"을 짚는 순서다.

- 4 · 5장의 **[굵은 괄호]** 는 화면에서 할 일이고, 그 아래 문단이 읽을 대본이다. 그대로 읽어도 되게 썼으니, 말하기 어색한 곳만 자기 말투로 바꾼다.
- 대본에 나오는 개수(160종, 8개 등)는 시연용 데이터를 막 넣은 상태 기준이다.
- 코드 설명의 줄 번호는 2026-11-27 의 코드 기준이다. 코드를 고치면 줄 번호도 다시 맞춘다.
- 시연에 쓰는 계정 · 글 · 댓글 · 추천은 [db/data_demo.sql](../db/data_demo.sql) 이 넣는다. 계정 아이디 · 비밀번호는 그 파일 머리말에 있다.

## 1. 과제 조건

- 코드 설명과 시나리오별 데모 설명으로 구성한다. 코드는 주요 부분만 설명하고, 구현 난이도에서 강조할 부분을 강조한다.
- 영상은 10분 이상이다(교수님 안내). 이 대본은 12 ~ 15분을 목표로 했다.
- 소스 코드가 읽히는 해상도로 찍는다. 화면과 함께 음성으로 설명한다.
- 평가 기준: ① 구현 난이도 ② 코드 무결성(오류 여부) ③ UI 화면 구성 ④ 데모 설명.
- 마감 2026-12-14. e-class 에 내고, 용량 때문에 올라가지 않으면 과제 공지의 이메일로 낸다.

## 2. 영상 구성

대본을 보통 속도로 읽으면 말하는 시간만 9 ~ 11분이고, 입력 · 클릭 시간을 더하면 13 ~ 15분쯤 걸린다.
장면 제목의 시간은 어림값이며 모두 더하면 14분 30초쯤이다. 연습해 보고 15분을 넘으면 장면 2의 비회원 추천, 장면 7의 쪽 넘기기처럼 같은 기능을 한 번 더 보여 주는 클릭부터 빼고, 12분보다 짧으면 화면마다 조금 더 천천히 보여 준다.

| 순서 | 내용 | 시간 | 주로 보여 주는 평가 기준 |
|---|---|---|---|
| 0 | 소개 | 45초 | ④ |
| 1 ~ 9 | 시나리오별 데모 | 8 ~ 10분 | ③ UI, ④ 데모 설명, ② 오류 처리 |
| 10 ~ 15 | 코드 설명 | 4 ~ 5분 | ① 구현 난이도, ② 무결성 |
| 16 | 마무리 | 30초 | |

## 3. 녹화 전 준비

- [ ] 시연용 데이터를 다시 넣는다. 연습하며 만든 글 · 댓글 · 추천과 `demonew` 계정도 함께 지워진다.
      `mysql -u root -p --default-character-set=utf8mb4 -e "source db/data_demo.sql"`
- [ ] 이클립스에서 서버를 켠다(Run on Server). 다른 Tomcat 이 켜져 있으면 8080 포트가 겹치므로 끈다.
- [ ] 브라우저는 시크릿(InPrivate) 창으로 연다. 비회원 상태로 시작하고, 회원가입 칸에 개인 정보가 자동 완성되지 않는다.
- [ ] 화면은 1920×1080. 이클립스 글꼴은 `Window > Preferences > General > Appearance > Colors and Fonts > Basic > Text Font` 에서 16pt 이상, 브라우저는 125% 정도로 키운다.
- [ ] 인터넷 연결을 확인한다. 버거 사진은 브랜드 사이트의 사진 주소라 인터넷이 없으면 CSS 로 그린 버거로 나온다.
- [ ] 알림을 끄고 북마크 바를 숨긴다. 마이크를 시험 녹음해 본다.
- [ ] `src/main/java/db.properties` 처럼 비밀번호가 든 파일은 화면에 열지 않는다.
- [ ] 화면 전체와 마이크를 함께 녹화할 수 있는 도구(예: OBS Studio)로 찍는다.

## 4. 시나리오별 데모

주소는 모두 `http://localhost:8080/OH_Burger/` 아래다.

### 0. 소개 (45초)

**[메인 화면을 띄워 둔다]**

안녕하세요. (학과 · 이름)입니다. 웹 응용 서비스 개발 프로젝트로 만든 OH Burger 를 소개하겠습니다.

OH Burger 는 국내 7개 프랜차이즈의 버거 160종과 사이드 146종의 영양 정보를 모아 티어로 비교하고, 꿀조합과 꿀팁을 나누는 서비스입니다. 서블릿, JSP, MySQL 로 만들었고 Tomcat 9 와 Java 21 을 썼습니다. 영양 정보는 브랜드 공식 홈페이지에서 가져왔고, 모르는 값은 비워 두고 "정보 없음"으로 보여 줍니다.

먼저 기능을 보여 드리고, 뒤에서 주요 코드를 설명하겠습니다.

### 1. 메인 티어표 — T-01, T-02 (1분)

**[메인 화면, 인기 탭]**

첫 화면은 버거 티어표입니다. 기준마다 상위 10퍼센트는 S, 30퍼센트까지 A, 70퍼센트까지 B, 90퍼센트까지 C, 나머지는 D 티어입니다. 인기 탭은 추천과 태그된 글, 조회수로 점수를 매깁니다.

**[단백질 → 열량 → 포화지방 → 가성비 탭을 차례로 누른다]**

탭을 누르면 기준이 바뀝니다. 가성비는 천 원당 단백질이라 가격이 없는 버거는 빠집니다.

**[단백질 탭 → 브랜드 "맘스터치" → "S 티어부터 ▼"]**

브랜드를 골라도 순위는 전체 기준 그대로라 티어가 바뀌지 않고, 이 버튼으로 D 티어부터 볼 수도 있습니다. 티어는 저장하지 않고 볼 때마다 SQL 로 계산해서, 추천이나 정보가 바뀌면 바로 반영됩니다.

### 2. 버거 도감 · 상세 — B-01, B-02 (40초)

**[머리글 "버거 도감" → 브랜드 "맘스터치" 체크, 정렬 "가격 낮은 순" → 검색]**

버거 도감에서는 이름 검색과 브랜드, 패티 종류, 정렬을 한 번에 걸 수 있습니다. 가격순으로 정렬하면 가격이 없는 버거는 맨 뒤에 "가격 정보 없음"으로 나옵니다.

**["휠렛버거" 상세 → 추천 버튼]**

상세 화면에는 영양 정보와 기준별 티어, 이 버거가 태그된 글이 나옵니다. 로그인하지 않고 추천을 누르면 로그인 안내가 나옵니다.

### 3. 사이드 티어표 — T-03 (20초)

**[머리글 "사이드 티어표" → 종류 "치킨"]**

사이드 146종도 같은 화면, 같은 SQL 로 티어표를 만들었습니다. 종류를 고르면 치킨은 치킨끼리 다시 순위를 매깁니다.

### 4. 룰렛 — R-01 (40초)

**[머리글 "룰렛" → 브랜드 "롯데리아", 가격 "6,000원 이하"]**

룰렛은 조건을 바꿀 때마다 서버에서 후보를 다시 받아 옵니다. 롯데리아에 6,000원 이하로 거니 후보가 8개입니다.

**["룰렛 돌리기" → 당첨 카드의 "상세 보기"]**

당첨 버거를 먼저 정하고, 그 칸이 화살표에 멈추도록 각도를 계산해서 돌립니다. 결과에서 바로 상세 화면으로 갈 수 있습니다.

### 5. 회원가입 · 로그인 — M-01, M-02 (1분)

**[회원가입 → 아이디 `demo01`, 비밀번호 확인을 다르게, 닉네임 `단백질러` → 가입하기]**

이미 있는 아이디와 닉네임으로, 비밀번호 확인도 다르게 가입해 보겠습니다. 칸마다 이유가 나오고 아이디와 닉네임은 그대로 남습니다. 형식은 브라우저가 먼저 막고, 중복과 규칙은 서버가 다시 검사합니다.

**[아이디 `demonew`, 닉네임 `새내기`로 가입 → 로그인. 비밀번호는 시연용 계정과 같은 값]**

올바르게 가입하면 로그인 화면으로 넘어갑니다. 비밀번호는 솔트를 붙여 SHA-256 으로 해시해 저장합니다.

### 6. 버거 추천 · 글쓰기 — B-03, P-03 (1분)

**["휠렛버거" 상세 → 추천 → 다시 눌러 취소 → 한 번 더 눌러 추천]**

로그인한 뒤 추천을 누르면 새로고침 없이 숫자만 바뀌고, 다시 누르면 취소됩니다.

**["이 버거로 글쓰기" → 태그 칸에서 "맥도날드 빅맥" 추가 → 분류 "꿀조합", 제목 · 내용 → 등록]**

"이 버거로 글쓰기"를 누르면 이 버거가 태그된 채로 열리고, 태그는 세 개까지 달 수 있습니다. 등록하면 글과 태그가 한 트랜잭션으로 저장됩니다.

### 7. 게시판 · 댓글 — P-01, P-02, P-04, P-05, C-01, C-02 (1분 10초)

**[게시판 → 분류 탭 "꿀팁" → "전체" → 쪽 번호 "2" → 검색 "휠렛" → 검색어를 지우고 정렬 "추천순"]**

게시판은 분류 탭, 제목과 내용 검색, 최신순과 추천순 정렬, 열 개씩 쪽 나누기를 지원합니다.

**[가성비왕의 "브랜드마다 최애 버거 하나씩 적어 봐요" → 추천 → 댓글 작성 → 내 댓글 삭제]**

다른 회원 글에는 추천과 댓글을 달 수 있고, 삭제 버튼은 내 댓글에만 보입니다.

**[6에서 쓴 내 글 → 수정 → 등록]**

내 글은 추천 버튼이 잠겨 있고, 수정하면 작성 시각 옆에 "수정됨"이 붙습니다. 권한은 버튼이 아니라 서블릿에서 다시 검사합니다.

### 8. 로그인이 풀려도 쓰던 글 지키기 (1분 10초) — 구현 난이도 강조

**[글쓰기 → 제목 · 내용 입력, 등록하지 않음 → 새 탭에서 로그아웃 → 원래 탭에서 등록]**

구현 난이도 면에서 강조하고 싶은 기능입니다. 글을 쓰는 사이 로그인이 풀린 상황을 만들려고 다른 탭에서 로그아웃하고 등록을 눌렀습니다. 로그인 화면으로 넘어갑니다.

**[로그인 → 되살아난 내용 확인 → 등록]**

다시 로그인하면 글쓰기 화면으로 돌아오고 쓰던 내용이 그대로 있습니다. 보낸 입력값을 세션에 맡겨 두었다가 로그인 뒤에 꺼내 주는 방식이고, 댓글과 관리자 화면에서도 똑같이 동작합니다.

### 9. 마이페이지 · 권한 · 관리자 — M-03, B-04 (2분)

**[머리글 "새내기 님" → 마이페이지]**

마이페이지에서는 내가 쓴 글과 추천한 버거를 모아 봅니다.

**[주소창에 `.../admin/burgers` 입력]**

일반 회원이 관리자 주소를 직접 열면 403 화면이 나옵니다. 메뉴를 숨기는 것만으로는 막을 수 없어서 필터가 관리자 주소 전체를 검사합니다.

**[로그아웃 → `demoadmin` 로그인 → 버거 관리 → 버거 등록: 브랜드 "롯데리아", 이름 "시연용 버거", 가격 · 열량 · 단백질 → 저장]**

관리자로 로그인하면 버거 관리 메뉴가 생깁니다. 버거를 저장하면 상세 화면으로 가는데, 볼 때마다 계산하기 때문에 티어가 바로 붙어 있습니다.

**[상세의 "수정" → 가격 변경 → 저장 → 버거 관리 목록에서 "시연용 버거" 삭제]**

수정하면 바뀐 가격으로 티어를 다시 계산하고, 삭제는 한 번 더 확인한 뒤 추천과 태그까지 함께 지웁니다.

**[게시판에서 새내기의 글 → 삭제]**

관리자는 다른 회원의 글을 지울 수 있지만 고칠 수는 없습니다.

**[주소창에 `.../nothing` 입력]**

없는 주소는 전용 404 화면으로 보여 주고, 예외 내용은 서버 로그에만 남깁니다. 이제 코드를 설명하겠습니다.

## 5. 코드 설명 (4 ~ 5분)

이클립스에서 **[코드]** 에 적힌 파일을 열고, 그 줄을 선택해 가며 읽는다.

### 10. 구조와 요청 흐름 (40초)

**[이클립스 Project Explorer 에서 패키지와 `WEB-INF/views` 를 펼친다]**

코드는 MVC 로 나눴습니다. web 패키지의 서블릿이 요청을 받고, dao 가 SQL 을 실행하고, JSP 는 화면만 그립니다. JSP 는 WEB-INF 안에 있어서 주소로 바로 열 수 없습니다.

**[코드]** [BurgerDetailServlet.java](../src/main/java/ohburger/web/BurgerDetailServlet.java#L36-L67) 36~67줄

상세 서블릿은 번호를 검사하고, DAO 로 찾고, 없으면 404 를 보낸 뒤 값을 담아 JSP 로 forward 합니다. SQL 은 모두 PreparedStatement 로 실행합니다.

### 11. 티어 계산 SQL (1분) — 구현 난이도

**[코드]** [TierDao.java](../src/main/java/ohburger/dao/TierDao.java#L33-L48) 33~48줄

가장 강조하고 싶은 부분은 티어 계산입니다. score 에서 기준 값을 구하고, ranked 에서 RANK 윈도 함수로 매긴 순위를 전체 개수로 나눠 상위 몇 퍼센트인지 구한 뒤, CASE 문으로 S 부터 D 까지 붙입니다. 브랜드 조건은 순위를 다 매긴 뒤 바깥 WHERE 에만 걸어서 걸러도 티어가 그대로이고, 사이드 티어표도 테이블 이름만 바꿔 이 쿼리를 씁니다.

**[코드]** [Metric.java](../src/main/java/ohburger/model/Metric.java#L15-L26) 15~26줄

기준은 enum 에 SQL 식 하나씩으로 정의했습니다. 가성비는 NULLIF 로 0으로 나누기를 막았고, 여기에 한 줄을 추가하면 탭과 배지가 같이 생깁니다.

### 12. 필터 체인과 입력값 보존 (1분) — 구현 난이도

**[코드]** [web.xml](../src/main/webapp/WEB-INF/web.xml#L16-L66) 16~66줄, [CsrfFilter.java](../src/main/java/ohburger/common/CsrfFilter.java#L30-L39) 30~39줄

요청은 인코딩, CSRF 차단, 로그인 정보 최신화, 로그인 검사, 관리자 검사 순서로 필터를 지납니다. 순서가 중요해서 web.xml 에 적었습니다. CSRF 필터는 POST 요청이 다른 사이트에서 왔으면 403 으로 거절하고, 최신화 필터는 요청마다 권한을 다시 읽어서 관리자 권한을 빼면 바로 반영됩니다.

**[코드]** [LoginFilter.java](../src/main/java/ohburger/common/LoginFilter.java#L32-L51) 32~51줄, [PendingForm.java](../src/main/java/ohburger/common/PendingForm.java#L34-L65) 34~65줄, [LoginServlet.java](../src/main/java/ohburger/web/LoginServlet.java#L63-L66) 63~66줄

로그인이 풀린 채 양식을 보내면 로그인 필터가 입력값을 PendingForm 에 맡깁니다. 크기 제한을 두었고, 로그인 뒤 같은 화면에서 한 번만 꺼냅니다. 로그인할 때는 changeSessionId 로 세션 번호를 바꿔 세션 고정 공격을 막으면서도, 맡겨 둔 값은 남게 했습니다.

### 13. 추천 토글 (35초)

**[코드]** [like.js](../src/main/webapp/js/like.js#L19-L51) 19~51줄, [LikeDao.java](../src/main/java/ohburger/dao/LikeDao.java#L36-L56) 36~56줄

추천은 fetch 에 X-Requested-With 헤더를 붙여 보냅니다. 다른 사이트의 양식으로는 이 헤더를 붙일 수 없어서 서버는 헤더 없는 요청을 거절합니다. DAO 는 먼저 DELETE 해 보고 지워진 게 없으면 INSERT 하고, 거의 동시에 두 번 와도 기본키 중복을 잡아 한 번만 들어갑니다.

### 14. 룰렛 (30초)

**[코드]** [roulette.js](../src/main/webapp/js/roulette.js#L134-L158) 134~158줄, [161~201줄](../src/main/webapp/js/roulette.js#L161-L201)

룰렛은 당첨 칸을 먼저 뽑고, 그 칸 가운데가 화살표에 오는 각도를 계산해 다섯 바퀴 이상 돌린 뒤, requestAnimationFrame 으로 점점 느려지게 그립니다. 조건을 빨리 바꿔서 늦게 도착한 예전 응답은 요청 번호로 버립니다.

### 15. 데이터 무결성 · 보안 (30초)

**[코드]** [PostDao.java](../src/main/java/ohburger/dao/PostDao.java#L147-L176) 147~176줄, [PasswordUtil.java](../src/main/java/ohburger/common/PasswordUtil.java#L28-L42) 28~42줄, [post.jsp](../src/main/webapp/WEB-INF/views/post.jsp#L26) 26줄

글과 태그는 한 트랜잭션으로 저장하고 실패하면 rollback 합니다. 비밀번호는 솔트와 SHA-256 으로 저장하고 MessageDigest.isEqual 로 비교합니다. 사용자가 쓴 글은 c:out 으로 출력해서 스크립트를 넣어도 실행되지 않습니다.
