# 데모 영상 시나리오

데모 영상(#10)을 찍을 때 보는 대본이다. 영상은 **시나리오별 데모**를 먼저 하고 **코드 설명**을 뒤에 붙인다.
기능을 먼저 보여 주고, 코드 설명에서 "앞에서 본 그 기능"을 짚는 순서다.

- 4 · 5장의 **[굵은 괄호]** 는 화면에서 할 일이고, 그 아래 문단이 읽을 대본이다. 그대로 읽어도 되게 썼으니, 말하기 어색한 곳만 자기 말투로 바꾼다.
- 대본에 나오는 개수(160종, 8개 등)는 시연용 데이터를 막 넣은 상태 기준이다.
- 코드 설명의 줄 번호는 2026-11-27 의 코드 기준이다. 코드를 고치면 줄 번호도 다시 맞춘다.
- 시연에 쓰는 계정 · 글 · 댓글 · 추천은 [db/data_demo.sql](../db/data_demo.sql) 이 넣는다. 계정 아이디 · 비밀번호는 그 파일 머리말에 있다.

## 1. 과제 조건

- 코드 설명과 시나리오별 데모 설명으로 구성한다. 코드는 주요 부분만 설명하고, 구현 난이도에서 강조할 부분을 강조한다.
- 소스 코드가 읽히는 해상도로 찍는다. 화면과 함께 음성으로 설명한다.
- 평가 기준: ① 구현 난이도 ② 코드 무결성(오류 여부) ③ UI 화면 구성 ④ 데모 설명.
- 마감 2026-12-14. e-class 에 내고, 용량 때문에 올라가지 않으면 과제 공지의 이메일로 낸다.

## 2. 영상 구성

길이 제한은 없다. 대본을 다 읽으면 20~25분, "(줄일 때 뺌)" 이 붙은 단계와 문단을 빼면 18~22분쯤 걸린다(말하는 속도와 클릭 시간에 따라 다르다).

| 순서 | 내용 | 시간 | 주로 보여 주는 평가 기준 |
|---|---|---|---|
| 0 | 소개 | 1분 30초 | ④ |
| 1 ~ 9 | 시나리오별 데모 | 11 ~ 13분 | ③ UI, ④ 데모 설명, ② 오류 처리 |
| 10 ~ 15 | 코드 설명 | 7 ~ 10분 | ① 구현 난이도, ② 무결성 |
| 16 | 마무리 | 30초 | |

## 3. 녹화 전 준비

- [ ] 시연용 데이터를 다시 넣는다. 연습하며 만든 글 · 댓글 · 추천과 `demonew` 계정도 함께 지워진다.
      `mysql -u root -p --default-character-set=utf8mb4 -e "source db/data_demo.sql"`
- [ ] 이클립스에서 서버를 켠다(Run on Server). 다른 Tomcat 이 켜져 있으면 8080 포트가 겹치므로 끈다.
- [ ] 브라우저는 시크릿(InPrivate) 창으로 연다. 비회원 상태로 시작하고, 회원가입 칸에 개인 정보가 자동 완성되지 않는다.
- [ ] 화면은 1920×1080. 이클립스 글꼴은 `Window > Preferences > General > Appearance > Colors and Fonts > Basic > Text Font` 에서 16pt 이상, 브라우저는 125% 정도로 키운다.
- [ ] 인터넷 연결을 확인한다. 버거 사진은 브랜드 사이트의 사진 주소라 인터넷이 없으면 CSS 로 그린 버거로 나온다.
- [ ] 알림을 끄고 북마크 바를 숨긴다. 마이크를 시험 녹음해 본다.
- [ ] `src/main/java/db.properties` 처럼 비밀번호가 든 파일은 화면에 열지 않는다.
- [ ] 화면 전체와 마이크를 함께 녹화할 수 있는 도구(예: OBS Studio)로 찍는다.

## 4. 시나리오별 데모

주소는 모두 `http://localhost:8080/OH_Burger/` 아래다.

### 0. 소개 (1분 30초)

**[메인 화면을 띄워 둔다]**

안녕하세요. (학과 · 이름)입니다. 웹 응용 서비스 개발 프로젝트로 만든 OH Burger 를 소개하겠습니다.

OH Burger 는 국내 프랜차이즈 햄버거를 영양 정보로 비교하는 서비스입니다. 맥도날드, 버거킹, 롯데리아, 맘스터치, KFC, 노브랜드버거, 프랭크버거 일곱 곳의 버거 160종과 사이드 메뉴 146종을 모았고, 단백질이나 열량 같은 기준으로 티어를 매겨 보여 줍니다. 회원은 게시판에서 꿀조합과 꿀팁을 나눌 수 있습니다.

서버는 서블릿과 JSP, 데이터베이스는 MySQL 로 만들었고, Tomcat 9, Java 21, JSTL 을 사용했습니다. 화면은 HTML, CSS, 자바스크립트로 만들었습니다.

영양 정보는 각 브랜드 공식 홈페이지에서 가져왔습니다. 가격은 160종 가운데 107종에만 있고, 그중 일부는 기사나 나무위키에 나온 매장 가격입니다. 모르는 값은 채워 넣지 않고 비워 둔 뒤, 화면에 "정보 없음"으로 보여 줍니다.

먼저 기능을 시나리오 순서대로 보여 드리고, 뒤에서 주요 코드를 설명하겠습니다.

### 1. 메인 티어표 — T-01, T-02 (1분 30초)

**[메인 화면, 인기 탭]**

첫 화면은 버거 티어표입니다. 기준마다 버거를 한 줄로 세워서, 상위 10퍼센트는 S, 30퍼센트까지는 A, 70퍼센트까지는 B, 90퍼센트까지는 C, 나머지는 D 티어로 나눕니다.

지금 보이는 인기 탭은 추천 수에 5를 곱하고, 그 버거가 태그된 글 수에 3을 곱하고, 조회수를 더한 점수로 순위를 매깁니다.

**[단백질 → 열량 → 포화지방 → 가성비 탭을 차례로 누른다]**

탭을 누르면 기준이 바뀝니다. 단백질은 많을수록 위에 오고, 열량과 포화지방은 낮을수록 위에 옵니다. 가성비는 천 원당 단백질입니다. 가격이 없는 버거는 계산할 수 없어서 이 탭에서는 빠집니다.

**[단백질 탭을 누르고 브랜드 "맘스터치"를 누른다]**

브랜드를 고르면 그 브랜드 버거만 남습니다. 이때 순위는 전체 버거를 기준으로 매긴 그대로라서, 걸러도 티어 글자가 바뀌지 않습니다. 예를 들어 화이트갈릭버거는 전체에서도 S 티어입니다.

**["S 티어부터 ▼" 를 누른다]**

이 버튼을 누르면 D 티어부터 거꾸로 볼 수 있습니다.

티어는 데이터베이스에 저장하지 않고, 화면을 열 때마다 SQL 로 계산합니다. 그래서 추천이 늘거나 영양 정보가 바뀌면 바로 반영됩니다. 이 부분은 뒤에서 코드로 설명하겠습니다.

### 2. 버거 도감 · 상세 — B-01, B-02 (1분 30초)

**[머리글 "버거 도감" → 검색 칸에 "새우" → 검색]**

버거 도감에서는 160종을 검색하고 비교할 수 있습니다. "새우"로 검색하면 이름에 새우가 들어간 버거만 나옵니다.

**[검색어를 지우고 브랜드 "맘스터치" 체크, 정렬 "가격 낮은 순" → 검색]**

브랜드, 패티 종류, 정렬을 한 번에 걸 수 있고, 조건이 주소에 남아서 새로고침해도 그대로입니다. 가격 낮은 순으로 정렬하면 가격 정보가 없는 버거는 맨 뒤에 "가격 정보 없음"으로 나옵니다. 값이 없는 버거는 어떤 정렬에서든 항상 뒤로 보내도록 했습니다.

**["휠렛버거"를 눌러 상세로 간다]**

상세 화면에는 영양 정보 표와 기준별 티어 배지가 있습니다. 아래에는 이 버거가 태그된 글이 추천 많은 순으로 나옵니다. 조회수는 같은 세션에서는 한 번만 오르게 했습니다.

**[추천 버튼을 누른다]**

지금은 로그인하지 않은 상태라서, 추천을 누르면 로그인이 필요하다는 안내가 나옵니다.

### 3. 사이드 티어표 — T-03 (40초)

**[머리글 "사이드 티어표"]**

사이드, 치킨, 디저트 146종도 티어표로 볼 수 있습니다. 버거 티어표와 같은 화면, 같은 SQL 을 쓰고 테이블만 사이드 메뉴로 바꿨습니다. 추천과 태그는 버거에만 있어서 사이드에는 인기 탭이 없습니다.

**[종류 "치킨"을 누른다]**

종류를 고르면 그 종류 안에서만 다시 순위를 매깁니다. 그래서 감자튀김과 치킨을 한 줄에 세우지 않고, 치킨끼리 비교할 수 있습니다.

### 4. 룰렛 — R-01 (1분)

**[머리글 "룰렛"]**

메뉴를 고르기 어려울 때 쓰는 룰렛입니다. 조건 없이 열면 160종이 모두 후보인데, 판에는 그중 12개를 무작위로 골라 올립니다.

**[가격 "6,000원 이하"를 고르고 브랜드 "프랭크버거"만 체크]**

조건을 바꿀 때마다 서버에서 후보를 다시 받아 옵니다. 프랭크버거는 가격 정보가 없어서 가격 조건을 걸면 후보가 하나도 없고, 돌리기 버튼이 잠깁니다.

**[프랭크버거를 끄고 "롯데리아" 체크 → "룰렛 돌리기"]**

롯데리아로 바꾸면 6,000원 이하 버거는 8개입니다. 돌려 보겠습니다. 당첨 버거를 먼저 정한 다음, 그 칸이 위쪽 화살표에 멈추도록 회전 각도를 계산해서 돌립니다.

**[당첨 카드의 "상세 보기"]**

당첨된 버거는 바로 상세 화면으로 이어집니다.

### 5. 회원가입 · 로그인 — M-01, M-02 (1분 30초)

**[머리글 "회원가입" → 아이디 `demo01`, 비밀번호와 확인을 서로 다르게, 닉네임 `단백질러` → 가입하기]**

이제 회원 기능입니다. 일부러 이미 있는 아이디와 닉네임을 넣고, 비밀번호 확인도 다르게 넣어 보겠습니다. 칸마다 이유가 나오고, 아이디와 닉네임은 입력한 값이 그대로 남습니다. 비밀번호는 다시 채워 주지 않습니다.

글자 수나 영문 · 숫자 같은 형식은 브라우저가 먼저 막고, 서버에서도 같은 규칙과 중복을 다시 검사합니다.

**[아이디 `demonew`, 닉네임 `새내기`로 가입한다. 비밀번호는 시연용 계정과 같은 값]**

올바르게 넣으면 가입이 끝나고 로그인 화면으로 넘어갑니다. 비밀번호는 회원마다 다른 솔트를 붙여 SHA-256 으로 해시한 값만 저장합니다.

**[(줄일 때 뺌) 비밀번호를 틀리게 넣어 로그인]**

비밀번호가 틀리면, 아이디와 비밀번호 중 어느 쪽이 틀렸는지는 알려 주지 않고 같은 문구를 보여 줍니다.

**[바르게 로그인한다]**

로그인하면 머리글에 닉네임이 나옵니다.

### 6. 버거 추천 · 글쓰기 — B-03, P-03 (1분 30초)

**[도감에서 "휠렛버거" 상세 → 추천 → 한 번 더 눌러 취소 → 다시 눌러 추천한 상태로 둔다]**

로그인한 상태로 추천을 누르면 화면이 새로 고쳐지지 않고 숫자만 바뀝니다. 한 번 더 누르면 취소됩니다. 자바스크립트의 fetch 로 요청을 보내고, 서버가 JSON 으로 돌려준 추천 수로 숫자만 바꾸는 방식입니다.

**["이 버거로 글쓰기" → 태그 칸에 "빅맥"을 치고 목록에서 "맥도날드 빅맥" 선택]**

"이 버거로 글쓰기"를 누르면 이 버거가 태그된 채로 글쓰기 화면이 열립니다. 태그는 버거 이름을 검색해서 세 개까지 달 수 있습니다.

**[(줄일 때 뺌) 제목에 공백만 넣고 등록]**

제목에 공백만 넣으면 브라우저는 통과시키지만, 서버가 앞뒤 공백을 지우고 다시 검사해서 막습니다. 쓰던 내용과 태그는 그대로 남아 있습니다.

**[분류 "꿀조합", 제목 · 내용을 쓰고 등록]**

등록하면 글과 버거 태그가 한 트랜잭션으로 저장되고, 글 상세 화면으로 넘어갑니다.

### 7. 게시판 · 댓글 — P-01, P-02, P-04, P-05, C-01, C-02 (1분 30초)

**[게시판 → 분류 탭 "꿀팁" → "전체" → 아래 쪽 번호 "2"]**

게시판은 꿀조합, 꿀팁, 자유 세 가지로 나뉘고, 한 쪽에 열 개씩 보여 줍니다.

**[검색 "휠렛" → 검색어를 지우고 정렬 "추천순"을 골라 검색]**

제목과 내용으로 검색할 수 있고, 최신순과 추천순으로 정렬할 수 있습니다. 검색어에 퍼센트 기호나 밑줄이 들어가도 SQL 의 와일드카드로 쓰이지 않게 처리했습니다.

**[가성비왕의 "브랜드마다 최애 버거 하나씩 적어 봐요" → 추천 → 댓글 작성 → 방금 쓴 댓글 삭제]**

다른 회원의 글에는 추천하고 댓글을 달 수 있습니다. 댓글 삭제 버튼은 내가 쓴 댓글에만 보입니다.

**[6에서 쓴 내 글을 연다 → 수정 → 등록]**

내 글에서는 추천 버튼이 잠겨 있습니다. 자기 글 추천은 화면에서 막고, 서버에서도 한 번 더 막습니다. 글을 수정하면 작성 시각 옆에 "수정됨"이 붙습니다. 수정과 삭제 버튼은 작성자에게만 보이지만, 권한 검사는 버튼이 아니라 서블릿에서 합니다.

### 8. 로그인이 풀려도 쓰던 글 지키기 (1분 30초) — 구현 난이도 강조

**[게시판 "글쓰기" → 분류 · 제목 · 내용을 쓰고, 아직 등록하지 않는다]**

이번에는 구현 난이도 면에서 강조하고 싶은 기능입니다. 글을 오래 쓰다 보면 그사이 로그인이 풀릴 수 있는데, 그 상황을 만들어 보겠습니다.

**[새 탭에서 사이트를 열고 로그아웃 → 원래 탭으로 돌아와 등록]**

다른 탭에서 로그아웃했으니 지금은 로그인이 풀린 상태입니다. 이대로 등록을 누르면 로그인 화면으로 넘어갑니다.

**[로그인한다]**

로그인하면 글쓰기 화면으로 돌아오고, 쓰던 분류와 제목, 내용이 그대로 되살아납니다. 로그인이 필요한 양식을 보낼 때 입력값을 세션에 잠깐 맡겨 두었다가, 로그인한 뒤에 꺼내 주는 방식입니다. 댓글, 글 수정, 관리자의 버거 등록과 수정에서도 똑같이 동작합니다.

**[등록한다]**

### 9. 마이페이지 · 권한 · 관리자 — M-03, B-04 (2분 30초)

**[머리글 "새내기 님" → 마이페이지]**

머리글의 닉네임을 누르면 마이페이지로 갑니다. 내가 쓴 글과 내가 추천한 버거를 모아서 보여 줍니다.

**[주소창에 `.../admin/burgers` 를 직접 입력]**

일반 회원이 관리자 주소를 직접 입력하면 403 화면이 나옵니다. 메뉴를 숨기는 것만으로는 막을 수 없어서, 관리자 주소 전체를 필터 하나가 검사하도록 했습니다.

**[로그아웃 → `demoadmin` 으로 로그인]**

관리자 계정으로 로그인하면 머리글에 "버거 관리" 메뉴가 생깁니다.

**[버거 관리 → 버거 등록 → (줄일 때 뺌) 브랜드 "롯데리아", 이름 "데리버거"로 저장]**

관리자는 버거를 등록, 수정, 삭제할 수 있습니다. 같은 브랜드에 이미 있는 이름으로 저장하면 중복이라고 알려 줍니다.

**[이름을 "시연용 버거"로 바꾸고 가격 · 열량 · 단백질을 넣어 저장]**

이름을 바꿔 저장하면 새 버거의 상세 화면으로 갑니다. 저장하자마자 티어 배지가 붙어 있는데, 티어를 저장해 두지 않고 볼 때마다 계산하기 때문입니다.

**[상세의 "수정" → 가격을 바꿔 저장]**

가격을 바꿔 저장하면, 바뀐 가격으로 다시 계산한 티어가 바로 보입니다.

**[버거 관리 목록에서 "시연용 버거" 삭제 → 확인]**

삭제는 되돌릴 수 없어서 한 번 더 묻습니다. 이 버거의 추천과 글 태그도 함께 지워집니다.

**[게시판에서 새내기가 쓴 글을 열고 삭제]**

관리자는 다른 회원의 글과 댓글을 지울 수 있습니다. 대신 수정 버튼은 없어서 남의 글을 고칠 수는 없습니다.

**[주소창에 `.../nothing` 을 입력]**

없는 주소를 열면 Tomcat 기본 오류 화면 대신 전용 404 화면이 나옵니다. 서버에서 예외가 나도 화면에는 내용을 보여 주지 않고 서버 로그에만 남깁니다.

여기까지가 기능 시연입니다. 이제 주요 코드를 설명하겠습니다.

### 11. 티어 계산 SQL (2분 30초) — 구현 난이도

**[코드]** [TierDao.java](../src/main/java/ohburger/dao/TierDao.java#L33-L48) 33~48줄

가장 강조하고 싶은 부분은 티어 계산입니다. 티어를 테이블에 저장하지 않고, 이 쿼리 하나로 볼 때마다 계산합니다.

WITH 절의 score 에서 버거마다 기준 값을 구하고, ranked 에서 RANK 윈도 함수로 순위를 매깁니다. 순위에서 1을 빼고 전체 개수로 나누면 상위 몇 퍼센트인지가 나오는데, 이 값을 p 라고 했습니다. 마지막에 CASE 문으로 p 가 0.1 보다 작으면 S, 0.3 보다 작으면 A 처럼 티어를 붙입니다.

값이 NULL 인 버거는 순위에서 빼고, 인기 기준에서는 0점인 버거도 뺍니다. 브랜드 조건은 순위를 다 매긴 뒤 바깥 WHERE 에만 걸었습니다. 그래서 브랜드로 걸러도 전체 기준 티어가 그대로 유지됩니다.

**[코드]** [Metric.java](../src/main/java/ohburger/model/Metric.java#L15-L26) 15~26줄

기준은 enum 으로 만들었고, 기준마다 SQL 식이 하나씩 있습니다. 가성비는 단백질에 천을 곱해 가격으로 나누는데, 가격이 0이면 NULLIF 로 NULL 이 되게 해서 0으로 나누는 문제를 막았습니다. 기준을 하나 늘리고 싶으면 여기에 한 줄만 추가하면, 티어표 탭과 상세 화면의 배지가 같이 생깁니다.

**[코드] (줄일 때 뺌)** [TierDao.java](../src/main/java/ohburger/dao/TierDao.java#L67-L78) 67~78줄

사이드 티어표는 같은 쿼리에 테이블 이름만 side_menu 로 바꿔 씁니다. 테이블 이름은 사용자 입력이 아니라 코드에 고정된 값만 넘기기 때문에 SQL 에 붙여도 안전합니다. 사이드의 종류 조건은 순위를 매기는 안쪽에 넣어서, 종류를 고르면 그 종류 안에서 순위가 다시 매겨집니다.

이렇게 계산으로 처리하니까, 추천이 늘거나 관리자가 정보를 고쳐도 따로 맞춰 줄 데이터가 없습니다.

### 12. 필터 체인과 입력값 보존 (2분 30초) — 구현 난이도

**[코드]** [web.xml](../src/main/webapp/WEB-INF/web.xml#L16-L66) 16~66줄

다음은 필터입니다. 모든 요청은 인코딩, CSRF 차단, 로그인 정보 최신화, 로그인 검사, 관리자 검사 순서로 필터를 지납니다. 순서가 중요해서 어노테이션 대신 web.xml 에 순서대로 적었습니다.

**[코드]** [CsrfFilter.java](../src/main/java/ohburger/common/CsrfFilter.java#L30-L39) 30~39줄

CSRF 필터는 내용을 바꾸는 요청이 어느 사이트에서 왔는지 Origin 헤더, 없으면 Referer 헤더로 확인하고, 이 사이트가 아니면 403 으로 거절합니다. 다른 사이트가 로그인한 회원 몰래 글을 지우거나 댓글을 달게 만드는 공격을 막기 위해서입니다.

**[코드] (줄일 때 뺌)** [SessionRefreshFilter.java](../src/main/java/ohburger/common/SessionRefreshFilter.java#L37-L49) 37~49줄

세션 갱신 필터는 요청마다 회원 정보를 DB 에서 다시 읽습니다. 세션에는 로그인할 때의 권한이 복사돼 있어서, 이렇게 하지 않으면 관리자 권한을 빼도 그 회원이 로그아웃할 때까지 관리자로 남기 때문입니다. 지워진 회원은 바로 로그아웃시킵니다.

**[코드]** [LoginFilter.java](../src/main/java/ohburger/common/LoginFilter.java#L32-L51) 32~51줄, [PendingForm.java](../src/main/java/ohburger/common/PendingForm.java#L34-L65) 34~65줄

로그인 필터는 비회원이 로그인이 필요한 화면을 열면, 돌아올 주소를 붙여 로그인 화면으로 보냅니다. 화면을 연 게 아니라 양식을 보낸 경우에는, 앞에서 본 것처럼 입력값을 PendingForm 에 맡깁니다. PendingForm 은 입력값을 세션에 넣어 두는데, 비회원 요청으로 세션이 커지지 않게 크기 제한을 두었고, 로그인한 뒤 같은 화면에서 한 번만 꺼내 씁니다.

**[코드]** [LoginServlet.java](../src/main/java/ohburger/web/LoginServlet.java#L63-L66) 63~66줄, [PostWriteServlet.java](../src/main/java/ohburger/web/PostWriteServlet.java#L39-L41) 39~41줄

로그인할 때는 changeSessionId 로 세션 번호를 새로 바꿉니다. 로그인 전에 알려진 세션 번호를 악용하는 세션 고정 공격을 막으면서도, 세션 안에 맡겨 둔 입력값은 그대로 남습니다. 글쓰기 서블릿은 맡겨 둔 값이 있으면 그 값으로 양식을 채우고 안내 문구를 띄웁니다.

### 13. 추천 토글: fetch 와 JSON (1분 30초)

**[코드]** [like.js](../src/main/webapp/js/like.js#L19-L51) 19~51줄

추천 버튼은 fetch 로 POST 요청을 보냅니다. 이때 X-Requested-With 라는 헤더를 붙이는데, 다른 사이트의 양식으로는 이런 헤더를 붙일 수 없어서, 서버는 이 헤더가 없는 요청을 거절합니다. 응답이 401 이면 로그인 안내를, 성공이면 받은 추천 수로 숫자만 바꿉니다. 응답이 오기 전에는 버튼을 잠가서 두 번 눌리지 않게 했습니다.

**[코드] (줄일 때 뺌)** [BurgerLikeServlet.java](../src/main/java/ohburger/web/BurgerLikeServlet.java#L35-L65) 35~65줄

서버는 헤더, 로그인 여부, 버거가 있는지를 차례로 확인하고 결과를 JSON 으로 돌려줍니다. 화면 이동이 아니라 JSON 으로 답해야 해서, 로그인 검사를 필터가 아니라 이 서블릿 안에서 합니다.

**[코드]** [LikeDao.java](../src/main/java/ohburger/dao/LikeDao.java#L36-L56) 36~56줄, [PostLikeServlet.java](../src/main/java/ohburger/web/PostLikeServlet.java#L57) 57줄

추천 토글은 먼저 DELETE 를 해 보고, 지워진 행이 있으면 취소, 없으면 INSERT 해서 추천합니다. 거의 동시에 요청이 두 번 와도 기본키 중복 예외를 잡아서 추천이 두 번 들어가지 않습니다. 버거 추천과 게시글 추천이 이 클래스 하나를 같이 씁니다. 게시글은 자기 글이면 화면에서 버튼을 잠그지만, 주소로 직접 요청해도 서버가 403 으로 막습니다.
