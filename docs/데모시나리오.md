# 데모 영상 시나리오

데모 영상(#10)을 찍을 때 보는 대본이다. 영상은 **시나리오별 데모**를 먼저 하고 **코드 설명**을 뒤에 붙인다.
기능을 먼저 보여 주고, 코드 설명에서 "앞에서 본 그 기능"을 짚는 순서다.

- 장면마다 **할 일**(누를 순서)과 **말할 내용**(요점)을 적었다. 말할 내용은 그대로 읽지 말고 자기 말로 바꿔 말한다.
- 코드 설명의 줄 번호는 2026-11-27 의 코드 기준이다. 코드를 고치면 줄 번호도 다시 맞춘다.
- 시연에 쓰는 계정 · 글 · 댓글 · 추천은 [db/data_demo.sql](../db/data_demo.sql) 이 넣는다. 계정 아이디 · 비밀번호는 그 파일 머리말에 있다.

## 1. 과제 조건

- 코드 설명과 시나리오별 데모 설명으로 구성한다. 코드는 주요 부분만 설명하고, 구현 난이도에서 강조할 부분을 강조한다.
- 소스 코드가 읽히는 해상도로 찍는다. 화면과 함께 음성으로 설명한다.
- 평가 기준: ① 구현 난이도 ② 코드 무결성(오류 여부) ③ UI 화면 구성 ④ 데모 설명.
- 마감 2026-12-14. e-class 에 내고, 용량 때문에 올라가지 않으면 과제 공지의 이메일로 낸다.

## 3. 녹화 전 준비

- [ ] 시연용 데이터를 다시 넣는다. 연습하며 만든 글 · 댓글 · 추천과 `demonew` 계정도 함께 지워진다.
      `mysql -u root -p --default-character-set=utf8mb4 -e "source db/data_demo.sql"`
- [ ] 이클립스에서 서버를 켠다(Run on Server). 다른 Tomcat 이 켜져 있으면 8080 포트가 겹치므로 끈다.
- [ ] 브라우저는 시크릿(InPrivate) 창으로 연다. 비회원 상태로 시작하고, 회원가입 칸에 개인 정보가 자동 완성되지 않는다.
- [ ] 화면은 1920×1080. 이클립스 글꼴은 `Window > Preferences > General > Appearance > Colors and Fonts > Basic > Text Font` 에서 16pt 이상, 브라우저는 125% 정도로 키운다.
- [ ] 인터넷 연결을 확인한다. 버거 사진은 브랜드 사이트의 사진 주소라 인터넷이 없으면 CSS 로 그린 버거로 나온다.
- [ ] 알림을 끄고 북마크 바를 숨긴다. 마이크를 시험 녹음해 본다.
- [ ] `src/main/java/db.properties` 처럼 비밀번호가 든 파일은 화면에 열지 않는다.
- [ ] 화면 전체와 마이크를 함께 녹화할 수 있는 도구(예: OBS Studio)로 찍는다.

## 4. 시나리오별 데모

주소는 모두 `http://localhost:8080/OH_Burger/` 아래다.

### 0. 소개 (1분)

할 일: 메인 화면을 띄워 둔다.

말할 내용
- OH Burger 는 국내 7개 프랜차이즈의 버거 160종과 사이드 146종의 영양 정보를 모아 티어로 비교하고, 꿀조합 · 꿀팁을 나누는 서비스다.
- 서블릿 · JSP · MySQL 로 만들었다. Tomcat 9, Java 21, JSTL 을 쓰고 화면은 HTML · CSS · JavaScript 다.
- 영양 정보는 각 브랜드 공식 홈페이지에서 조회했다. 가격은 107종에만 있고(일부는 기사 · 나무위키의 매장 가격), 모르는 값은 비워 두고 "정보 없음"으로 보여 준다.

### 1. 메인 티어표 — T-01, T-02 (1분 30초)

할 일
1. 비회원으로 메인을 연다. 기본 탭은 "인기"다.
2. 탭을 단백질 → 열량 → 포화지방 → 가성비 순서로 누른다.
3. 단백질 탭에서 브랜드 "맘스터치"를 누른다. 맘스터치 버거만 남지만 티어 글자는 전체 기준 그대로다.
4. "S 티어부터 ▼" 를 눌러 D 티어부터 본다.

말할 내용
- 기준마다 상위 10% 는 S, 30% 까지 A, 70% 까지 B, 90% 까지 C, 나머지는 D 다.
- 인기 점수는 추천 × 5 + 그 버거가 태그된 글 × 3 + 조회수다. 티어를 저장하지 않고 볼 때마다 계산해서 추천하면 바로 반영된다.
- 가성비는 1,000원당 단백질이다. 가격이 없는 버거는 이 탭에서 빠진다.
- 브랜드 필터는 보여 주는 것만 거르고 순위는 전체로 매겨서, 걸러도 티어가 바뀌지 않는다. (코드 설명 11)

### 2. 버거 도감 · 상세 — B-01, B-02 (1분 30초)

할 일
1. 머리글 "버거 도감" → 검색 칸에 "새우" → 검색. 새우버거들이 나온다.
2. 검색어를 지우고 브랜드 "맘스터치"를 체크, 정렬 "가격 낮은 순" → 검색. 가격이 없는 버거는 맨 뒤에 "가격 정보 없음"으로 나온다.
3. "휠렛버거"를 눌러 상세로 간다. 영양 정보 표, 기준별 티어 배지, 이 버거가 태그된 글을 보여 준다.
4. 추천 버튼을 누른다. 비회원이라 "추천하려면 로그인이 필요합니다." 가 나온다.

말할 내용
- 검색어 · 브랜드 · 패티 · 정렬이 한 번에 걸리고 주소에 남아서 새로고침해도 그대로다.
- 값이 없는 버거는 어떤 정렬이든 맨 뒤로 보낸다.
- 상세를 열면 조회수가 오르는데, 같은 세션에서는 한 번만 오른다.

### 3. 사이드 티어표 — T-03 (40초)

할 일
1. 머리글 "사이드 티어표". 기본은 단백질 탭이다.
2. 종류 "치킨"을 누른다. 치킨끼리만 다시 순위를 매긴다.

말할 내용
- 버거 티어표와 같은 화면, 같은 티어 SQL 을 쓰고 테이블만 바꿨다.
- 사이드에는 인기 탭이 없다. 추천 · 태그 기능이 버거에만 있어서다.

### 4. 룰렛 — R-01 (1분)

할 일
1. 머리글 "룰렛". 조건 없이 열면 "조건에 맞는 버거 160개 (그중 12개를 무작위로 올림)" 이 나온다.
2. 가격 "6,000원 이하", 브랜드 "프랭크버거"만 체크 → "조건에 맞는 버거가 없습니다. 조건을 바꿔 보세요." 가 나오고 돌리기 버튼이 잠긴다. 프랭크버거는 가격 정보가 없어 가격 조건에서 빠진다.
3. 프랭크버거를 끄고 "롯데리아"를 체크 → "조건에 맞는 버거 8개".
4. "룰렛 돌리기" → 4초 동안 돌고 당첨 카드가 나온다 → "상세 보기".

말할 내용
- 조건을 바꿀 때마다 서버에서 후보를 JSON 으로 받아 판을 다시 그린다.
- 당첨을 먼저 뽑고, 그 칸이 화살표에 오도록 회전 각도를 계산한다. (코드 설명 14)

### 5. 회원가입 · 로그인 — M-01, M-02 (1분 30초)

할 일
1. 머리글 "회원가입". 아이디 `demo01`(이미 있는 아이디), 비밀번호와 확인을 서로 다르게, 닉네임 `단백질러`(이미 있는 닉네임)로 가입한다.
   → 칸마다 "이미 사용 중인 아이디입니다." · "비밀번호가 서로 다릅니다." · "이미 사용 중인 닉네임입니다." 가 나오고, 아이디 · 닉네임은 입력한 값이 남는다.
2. 아이디 `demonew`, 닉네임 `새내기`로 가입한다. 비밀번호는 시연용 계정과 같은 값을 쓰면 헷갈리지 않는다.
   → 로그인 화면에 "가입이 완료되었습니다. 로그인해 주세요."
3. (줄일 때 뺌) 비밀번호를 틀리게 넣는다 → "아이디 또는 비밀번호가 올바르지 않습니다."
4. 바르게 로그인한다 → 머리글에 "새내기 님".

말할 내용
- 길이 · 글자 종류는 브라우저가 먼저 막고, 서버가 같은 규칙과 중복을 다시 검사한다.
- 비밀번호는 회원마다 다른 솔트를 붙여 SHA-256 으로 해시해 저장한다. (코드 설명 15)

### 6. 버거 추천 · 글쓰기 — B-03, P-03 (1분 30초)

할 일
1. 도감에서 "휠렛버거" 상세 → 추천. 새로고침 없이 숫자가 오른다. 한 번 더 누르면 취소된다. 다시 눌러 추천한 상태로 둔다.
2. "이 버거로 글쓰기" → 휠렛버거가 태그된 채로 열린다. 태그 칸에 "빅맥"을 치고 목록에서 "맥도날드 빅맥"을 골라 하나 더 단다.
3. (줄일 때 뺌) 제목에 공백만 넣고 등록 → 서버가 "제목을 입력해 주세요." 를 돌려주고 쓴 내용과 태그는 남는다.
4. 분류 "꿀조합", 제목 · 내용을 쓰고 등록 → 글 상세 화면.

말할 내용
- 추천은 fetch 로 보내고 JSON 으로 받아 숫자만 바꾼다. (코드 설명 13)
- 글과 버거 태그는 한 트랜잭션으로 저장한다. 태그는 최대 3개다. (코드 설명 15)

### 7. 게시판 · 댓글 — P-01, P-02, P-04, P-05, C-01, C-02 (1분 30초)

할 일
1. 게시판 목록: 분류 탭 "꿀팁" → "전체" → 아래 쪽 번호 "2" (한 쪽에 10개).
2. 검색 "휠렛" → 제목 · 내용에 휠렛이 들어간 글만 남는다. 검색어를 지우고 정렬 "추천순"을 골라 검색 → 추천이 많은 글부터.
3. 가성비왕의 "브랜드마다 최애 버거 하나씩 적어 봐요" → 추천 → 댓글을 쓴다 → 방금 쓴 내 댓글을 삭제한다.
4. 6에서 쓴 내 글 → 추천 버튼이 잠겨 있고 "자기 글은 추천할 수 없습니다." 가 보인다 → 수정 → 제목 옆에 "(수정됨)".

말할 내용
- 자기 글 추천은 화면에서 버튼을 잠그고, 서버도 따로 403 으로 막는다.
- 수정 · 삭제 버튼은 작성자에게만 보이지만, 권한은 서블릿에서 다시 검사한다.
- 조회수도 세션마다 한 번만 오른다. 내 글을 다시 열어도 조회수가 그대로다.

### 8. 로그인이 풀려도 쓰던 글 지키기 (1분) — 구현 난이도 강조

할 일
1. 게시판 "글쓰기"를 열고 분류 · 제목 · 내용을 쓴다. 아직 등록하지 않는다.
2. 새 탭에서 사이트를 열고 로그아웃한다. 오래 쓰다가 세션이 끝난 상황이다.
3. 원래 탭으로 돌아와 등록 → 로그인 화면으로 간다.
4. 로그인하면 글쓰기 화면으로 돌아오고, "로그인이 풀려 다시 로그인했습니다. 쓰던 내용을 되살렸으니 확인하고 등록해 주세요." 와 함께 쓰던 내용이 그대로 있다.
5. 등록한다.

말할 내용
- 글을 오래 쓰다 세션이 끝나도 내용이 사라지지 않게 했다. 댓글, 글 수정, 관리자의 버거 등록 · 수정도 같다. (코드 설명 12)

### 9. 마이페이지 · 권한 · 관리자 — M-03, B-04 (2분)

할 일
1. 머리글 "새내기 님" → 마이페이지. 내가 쓴 글과 내가 추천한 버거가 나온다.
2. 주소창에 `.../admin/burgers` 를 직접 입력 → 403 "권한이 없습니다".
3. 로그아웃하고 `demoadmin` 으로 로그인 → 머리글에 "버거 관리" 메뉴가 생긴다.
4. 버거 관리 → 버거 등록.
   (줄일 때 뺌) 브랜드 "롯데리아", 이름 "데리버거"로 저장 → "같은 브랜드에 같은 이름의 버거가 이미 있습니다."
   이름을 "시연용 버거"로 바꾸고 가격 · 열량 · 단백질을 넣어 저장 → 새 버거의 상세 화면으로 가고 티어 배지가 바로 붙어 있다.
   상세의 "수정"에서 가격을 바꿔 저장 → 바뀐 가격과 다시 계산된 티어가 보인다.
   버거 관리 목록에서 "시연용 버거"를 삭제한다(한 번 더 묻는다).
5. 게시판에서 새내기가 쓴 글을 연다. 관리자에게는 수정 버튼 없이 삭제 버튼만 보인다. 삭제한다.
6. 없는 주소(`.../nothing`)를 연다 → 404 "화면을 찾을 수 없습니다".

말할 내용
- 관리자 주소는 AdminFilter 가 한곳에서 막는다. 메뉴를 숨기는 것은 편의일 뿐이다.
- 관리자는 남의 글 · 댓글을 지울 수 있지만 고칠 수는 없다.
- 오류는 Tomcat 기본 화면 대신 전용 화면으로 보여 주고, 예외 내용은 화면에 내지 않고 서버 로그에만 남긴다.

## 5. 코드 설명 (약 7분)

이클립스에서 파일을 열고 해당 줄을 선택해 가며 설명한다.

### 10. 구조와 요청 흐름 (1분)

보여 줄 코드
- Project Explorer: `ohburger.common`(DB 연결 · 필터 · 공통), `dao`(SQL), `model`, `web`(서블릿 · 입력 검사), `WEB-INF/views`(JSP)
- [BurgerDetailServlet.java](../src/main/java/ohburger/web/BurgerDetailServlet.java#L36-L67) 36~67줄

말할 내용
- 서블릿이 요청을 받고, DAO 가 SQL 을 실행하고, JSP 는 화면만 그린다(MVC).
- 상세 서블릿: 번호 검사 → DAO 조회 → 없으면 404 → 세션당 한 번 조회수 → 값을 담아 burger.jsp 로 forward.
- JSP 는 WEB-INF 안에 있어 주소로 바로 열 수 없다. SQL 은 모두 PreparedStatement 로 실행한다.

### 11. 티어 계산 SQL (1분 30초) — 구현 난이도

보여 줄 코드
- [TierDao.java](../src/main/java/ohburger/dao/TierDao.java#L33-L48) 33~48줄: 티어 쿼리
- [Metric.java](../src/main/java/ohburger/model/Metric.java#L15-L26) 15~26줄: 기준별 SQL 식
- [TierDao.java](../src/main/java/ohburger/dao/TierDao.java#L67-L78) 67~78줄: 사이드 티어표

말할 내용
- `WITH` 로 기준 값을 구하고(score), `RANK() OVER` 와 `COUNT(*) OVER ()` 로 백분위 p 를 구해(ranked), `CASE` 로 S ~ D 를 붙인다.
- 순위는 안쪽에서 전체로 매기고 브랜드 조건은 바깥 `WHERE` 에만 걸어서, 필터를 걸어도 티어가 바뀌지 않는다.
- 값이 NULL 인 버거는 빠지고, 인기는 0점도 뺀다.
- 기준은 enum 에 SQL 식 하나로 있다. 가성비는 `ROUND(protein_g * 1000 / NULLIF(price, 0), 1)` 이다. 기준을 늘리려면 한 줄만 넣으면 티어표 탭과 상세 배지가 같이 생긴다.
- 사이드 티어표는 같은 쿼리에 테이블 이름과 종류 조건만 바꿔 쓴다.
- 티어를 저장하지 않으니 추천 · 수정이 바로 반영되고, 따로 맞춰 줄 데이터가 없다.

### 12. 필터 체인과 입력값 보존 (1분 30초) — 구현 난이도

보여 줄 코드
- [web.xml](../src/main/webapp/WEB-INF/web.xml#L16-L66) 16~66줄: 필터 순서
- [CsrfFilter.java](../src/main/java/ohburger/common/CsrfFilter.java#L30-L39) 30~39줄
- [SessionRefreshFilter.java](../src/main/java/ohburger/common/SessionRefreshFilter.java#L37-L49) 37~49줄
- [LoginFilter.java](../src/main/java/ohburger/common/LoginFilter.java#L32-L51) 32~51줄
- [PendingForm.java](../src/main/java/ohburger/common/PendingForm.java#L34-L65) 34~65줄
- [LoginServlet.java](../src/main/java/ohburger/web/LoginServlet.java#L63-L66) 63~66줄, [PostWriteServlet.java](../src/main/java/ohburger/web/PostWriteServlet.java#L39-L41) 39~41줄

말할 내용
- 필터는 인코딩 → 다른 사이트 요청 차단(CSRF) → 로그인 정보 최신화 → 로그인 검사 → 관리자 검사 순서로 돈다. 순서가 중요해서 `@WebFilter` 대신 web.xml 에 적었다.
- CSRF: 내용을 바꾸는 요청의 Origin(없으면 Referer)이 이 사이트가 아니면 403 으로 거절한다.
- 세션 갱신: 요청마다 회원의 닉네임 · 권한을 DB 에서 다시 읽는다. 관리자 권한을 빼면 바로 반영되고, 지워진 회원은 로그아웃된다.
- 로그인 검사: 비회원이 화면(GET)을 열면 돌아올 주소를 넘기고, 양식(POST)을 보내면 입력값을 PendingForm 에 맡긴 뒤 로그인 화면으로 보낸다.
- PendingForm 은 입력값을 세션에 맡기고(크기 제한 있음), 로그인 뒤 같은 화면에서 한 번만 꺼낸다.
- 로그인할 때 `changeSessionId()` 로 세션 번호만 바꾼다. 세션 고정 공격을 막으면서 맡겨 둔 입력값은 그대로 남는다.

### 13. 추천 토글: fetch 와 JSON (1분)

보여 줄 코드
- [like.js](../src/main/webapp/js/like.js#L19-L51) 19~51줄
- [BurgerLikeServlet.java](../src/main/java/ohburger/web/BurgerLikeServlet.java#L35-L65) 35~65줄
- [LikeDao.java](../src/main/java/ohburger/dao/LikeDao.java#L36-L56) 36~56줄

말할 내용
- 버튼을 누르면 fetch 로 POST 하고 `X-Requested-With: fetch` 헤더를 붙인다. 다른 사이트의 양식으로는 이 헤더를 붙일 수 없어서, 헤더가 없으면 서버가 거절한다.
- 응답 코드로 화면을 나눈다: 401 이면 로그인 안내, 403 이면 자기 글 안내, 성공이면 숫자만 바꾼다. 응답이 오기 전에는 버튼을 막아 두 번 눌리지 않게 한다.
- 자기 글은 화면에서 버튼을 잠그지만, 주소로 직접 요청해도 [PostLikeServlet.java](../src/main/java/ohburger/web/PostLikeServlet.java#L57) 57줄이 403 으로 막는다.
- 토글은 DELETE 해서 지워지면 취소, 아니면 INSERT 한다. 거의 동시에 두 번 오면 기본키 중복을 잡아 그대로 둔다. 버거 추천과 게시글 추천이 이 클래스 하나를 같이 쓴다.

### 15. 데이터 무결성 · 보안 (1분)

보여 줄 코드
- [PostDao.java](../src/main/java/ohburger/dao/PostDao.java#L147-L176) 147~176줄: 트랜잭션
- [JoinServlet.java](../src/main/java/ohburger/web/JoinServlet.java#L75-L86) 75~86줄: 중복 가입 경쟁
- [PasswordUtil.java](../src/main/java/ohburger/common/PasswordUtil.java#L28-L42) 28~42줄
- [post.jsp](../src/main/webapp/WEB-INF/views/post.jsp#L26) 26줄: `<c:out>`

- [DB.java](../src/main/java/ohburger/common/DB.java#L34-L49) 34~49줄: 연결 풀

말할 내용
- 글과 버거 태그를 한 트랜잭션으로 넣는다. 실패하면 rollback 하고, 연결이 풀로 돌아가므로 finally 에서 자동 커밋을 되돌린다.
- 중복 검사와 INSERT 사이에 같은 아이디가 먼저 가입되면 UNIQUE 위반을 잡아 같은 오류 문구로 보여 준다.
- 비밀번호는 솔트 + SHA-256 이고, 비교는 `MessageDigest.isEqual` 로 해서 비교 시간으로 값이 새지 않게 했다.
- 사용자가 쓴 글은 `<c:out>` 으로 이스케이프해서 글에 스크립트를 넣어도 실행되지 않는다.
- 정렬할 때 `price IS NULL` 을 먼저 둬서 값이 없는 버거를 항상 맨 뒤로 보낸다.
- DB 연결은 Tomcat 에 들어 있는 tomcat-jdbc 연결 풀을 쓰고, 모든 DAO 가 try-with-resources 로 빌려 쓰고 돌려준다.
