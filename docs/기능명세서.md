# OH Burger 기능 명세서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (2026-11-14) |
| 서비스 | 국내 프랜차이즈 햄버거 위키 · 티어표 · 꿀팁 커뮤니티 |
| 기술 스택 | Java Servlet / JSP, MySQL, Tomcat, HTML · CSS · JS |
| 구조 | MVC (Servlet = 컨트롤러, JSP = 뷰, DAO = DB 접근) |

## 1. 서비스 개요

국내 햄버거 프랜차이즈 7곳의 버거 메뉴를 한곳에서 조회하고, 기준별 티어표로 비교하며,
사용자끼리 꿀조합과 꿀팁을 공유하는 웹 서비스.

- **대상 브랜드**: 맥도날드, 버거킹, 롯데리아, 맘스터치, KFC, 노브랜드버거, 프랭크버거
- **대상 메뉴**: 각 브랜드의 버거 메뉴 전체 (단품 기준, 사이드 · 음료 · 세트 제외)

## 2. 사용자 구분

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 비회원 | 로그인하지 않은 방문자 | 버거 · 티어표 · 게시글 조회, 룰렛 |
| 회원 | 로그인한 사용자 | 비회원 기능 + 버거 추천, 글 · 댓글 작성, 게시글 추천 |
| 관리자 | `role = ADMIN` 인 회원 | 회원 기능 + 버거 데이터 관리, 모든 글 · 댓글 삭제 |

## 4. 기능 상세

### 4.1 회원

**M-01 회원가입**

- 입력: 아이디(영문 · 숫자 4~20자), 비밀번호(8자 이상), 비밀번호 확인, 닉네임(2~10자)
- 처리: 아이디 · 닉네임 중복 검사 → 비밀번호를 솔트와 함께 해시(SHA-256)해 저장
- 결과: 성공 시 로그인 화면으로 이동
- 예외: 형식 오류, 중복, 비밀번호 불일치 시 입력 화면에 사유 표시 (입력값은 유지)

**M-02 로그인 / 로그아웃**

- 입력: 아이디, 비밀번호
- 처리: 해시 비교 후 세션에 회원 번호 · 닉네임 · 권한 저장
- 결과: 로그인 전에 보던 화면으로 복귀. 로그아웃 시 세션 무효화 후 메인으로 이동
- 예외: 불일치 시 "아이디 또는 비밀번호가 올바르지 않습니다" (어느 쪽이 틀렸는지는 알리지 않음)
- 로그인이 필요한 주소에 비회원이 접근하면 필터가 로그인 화면으로 보냄

**M-03 마이페이지 (선택)**

- 내가 쓴 글 목록(최신순), 내가 추천한 버거 목록(최근에 추천한 순)을 한 화면에 보여 준다
- 회원 번호는 세션에서만 읽으므로 다른 회원의 것은 볼 수 없다. 비회원은 필터가 로그인 화면으로 보낸다
- 머리글의 닉네임을 누르면 들어간다

### 4.2 버거 위키

**B-01 버거 목록**

- 표시: 이미지, 브랜드, 이름, 가격, 열량, 단백질, 추천 수
- 검색: 버거 이름 (부분 일치)
- 필터: 브랜드(복수 선택), 패티 종류(소고기 / 치킨 / 새우 · 생선 / 기타)
- 정렬: 이름, 가격, 열량, 단백질, 포화지방, 추천 수 (각각 오름 · 내림)

**B-02 버거 상세**

- 표시
  - 기본 정보: 이미지, 브랜드, 이름, 설명, 가격, 패티 종류
  - 영양 정보: 중량, 열량, 단백질, 포화지방, 당류, 나트륨
  - 티어 배지 4종 (인기 · 단백질 · 열량 · 포화지방)
  - 추천 수와 추천 버튼
  - 이 버거가 태그된 게시글 목록 (추천 순 상위 5개 + 전체 보기 링크)
- 처리: 조회수 1 증가. 같은 세션에서 같은 버거는 한 번만 증가
- 예외: 없는 버거 번호면 404 화면

**B-03 버거 추천**

- 회원 1명이 버거 1개에 1회. 다시 누르면 취소 (토글)
- 페이지 새로고침 없이 처리 (fetch), 응답으로 최신 추천 수를 받아 화면 갱신
- 예외: 비회원이 누르면 로그인 안내

**B-04 버거 관리 (선택)**

- 관리자가 버거를 등록 · 수정 · 삭제. 구현하지 않을 경우 초기 데이터 SQL로만 관리

### 4.3 티어표

**T-01 메인 티어표**

- 메인 화면에 탭 4개: 인기 / 단백질 / 열량 / 포화지방
- 각 탭은 S · A · B · C · D 다섯 줄로 구성, 줄마다 해당 티어의 버거 카드(이미지 · 이름 · 브랜드 · 기준 수치) 나열
- 버거 카드를 누르면 버거 상세(B-02)로 이동

**T-02 필터 · 정렬 전환**

- 브랜드 필터: 선택한 브랜드의 버거만 표시. 티어 자체는 전체 버거 기준으로 계산한 값을 유지
- 정렬 방향 전환: 티어 줄 순서를 뒤집어 "많은 순 / 적은 순"으로 볼 수 있음

**티어 산출 규칙**

| 티어표 | 기준 값 | S에 가까운 쪽 |
|---|---|---|
| 인기 | 추천 수×5 + 태그된 게시글 수×3 + 조회수×1 | 높을수록 |
| 단백질 | 단백질(g) | 높을수록 |
| 열량 | 열량(kcal) | 낮을수록 |
| 포화지방 | 포화지방(g) | 낮을수록 |

1. 기준 값으로 전체 버거의 순위를 매긴다. 값이 같으면 같은 순위(공동 순위)로 둔다.
2. 순위 백분율 `p = (순위 - 1) / 대상 버거 수` 를 구한다.
3. `p` 로 티어를 정한다.

| 티어 | 조건 | 비중 |
|---|---|---|
| S | p < 0.10 | 상위 10% |
| A | p < 0.30 | 다음 20% |
| B | p < 0.70 | 다음 40% |
| C | p < 0.90 | 다음 20% |
| D | 그 외 | 하위 10% |

- 가격이 비어 있는 버거(브랜드가 사이트에 가격을 공개하지 않고 다른 출처에서도 확인하지 못함)는 "가격 정보 없음"으로 표시하고,
  가격 정렬에서는 맨 뒤로, 룰렛의 가격 상한 조건을 걸었을 때는 후보에서 제외한다
- 기준 값이 비어 있는 버거(영양 정보 미공개)는 해당 티어표에서 제외하고 상세 화면에 "정보 없음"으로 표시
- 인기 점수가 0인 버거는 티어를 매기지 않고 "집계 중"으로 표시
- 티어는 저장하지 않고 조회할 때마다 계산한다 (버거 수가 200개 안팎이라 부담 없음)

### 4.4 게시판

**P-01 게시글 목록**

- 분류: 꿀조합 / 꿀팁(재료 추가 · 맛있게 먹는 법) / 자유
- 표시: 분류, 제목, 태그된 버거, 작성자 닉네임, 작성일, 조회수, 추천 수, 댓글 수
- 검색: 제목 + 내용 (부분 일치)
- 정렬: 최신순, 추천순
- 페이징: 한 화면에 10개

**P-02 게시글 상세**

- 표시: 제목, 분류, 본문, 태그된 버거(누르면 버거 상세로 이동), 작성자, 작성일, 조회수, 추천 수, 댓글 목록
- 처리: 조회수 1 증가 (세션당 1회)
- 본문과 댓글은 출력 시 HTML 이스케이프 처리

**P-03 게시글 작성**

- 입력: 분류(필수), 제목(필수, 100자 이내), 본문(필수, 5000자 이내), 버거 태그(선택, 최대 3개)
- 버거 태그: 버거 이름을 검색해 선택. 태그된 글은 해당 버거 상세 화면에 노출
- 예외: 필수값 누락 · 길이 초과 시 입력 화면에 사유 표시

**P-04 게시글 수정 · 삭제**

- 수정은 작성자만, 삭제는 작성자와 관리자
- 삭제 시 댓글 · 추천 · 버거 태그도 함께 삭제
- 예외: 권한 없는 요청은 403 화면

**P-05 게시글 추천**

- 회원 1명이 게시글 1개에 1회, 토글. 자기 글은 추천할 수 없음
- 페이지 새로고침 없이 처리

### 4.5 댓글

**C-01 댓글 작성**: 본문(필수, 500자 이내). 작성 후 해당 게시글 상세로 복귀

**C-02 댓글 삭제**: 작성자와 관리자만 가능

### 4.6 룰렛

**R-01 조건부 랜덤 버거 룰렛**

- 조건 입력 (모두 선택 사항)
  - 브랜드 (복수 선택)
  - 가격 상한 (원): 6,000 / 8,000 / 10,000원 중 선택
  - 열량 상한 (kcal): 450 / 550 / 650 / 800kcal 중 선택
  - 상한을 걸면 그 값이 없는 버거(가격 · 열량 미공개)는 후보에서 제외한다
  - 패티 종류
- 처리
  1. 서버가 조건에 맞는 버거 목록을 JSON으로 응답
  2. 화면에서 후보들로 룰렛을 구성하고 회전 애니메이션 후 1개를 뽑음
  3. 후보가 12개를 넘으면 그중 12개를 무작위로 골라 룰렛에 올림
- 결과: 당첨 버거 카드 표시 + "상세 보기", "다시 돌리기" 버튼
- 예외: 조건에 맞는 버거가 없으면 "조건에 맞는 버거가 없습니다" 안내, 1개뿐이면 바로 결과 표시

## 6. 공통 요구사항

- **보안**: 모든 SQL은 `PreparedStatement` 사용, 사용자 입력 출력 시 HTML 이스케이프, 비밀번호는 해시 저장
- **권한 검사**: 로그인 · 작성자 · 관리자 확인은 화면이 아니라 서버(필터 · 서블릿)에서 수행
- **오류 처리**: 404 · 403 · 500 전용 화면 제공, 예외 내용은 사용자에게 노출하지 않고 서버 로그에 기록
- **인코딩**: 요청 · 응답 · DB 모두 UTF-8
- **화면**: 공통 헤더(로고, 메뉴, 로그인 상태) · 푸터를 JSP include로 재사용, 폭 1280px 기준에 모바일 폭에서도 깨지지 않게 구성

## 7. 범위에서 제외한 것

- 판매량 기반 순위 (브랜드가 메뉴별 판매량을 공개하지 않음)
- 외부 언급량 기반 화제성 순위 (외부 API 키가 필요해 제외)
- 사이드 · 음료 · 세트 메뉴, 매장 위치, 주문 · 결제
- 게시글 이미지 첨부, 대댓글, 신고 기능
